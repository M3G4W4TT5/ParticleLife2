# Discoveries and local sharing

Open **Files** for the discovery library. Search matches display names, descriptions, tags and filenames. Favourite and recent views use local metadata; up to 300 matching items are shown, so refine the search for larger folders. Rename changes the library's display name, preserving the scientific filename and its bound viewer companion. Descriptions, tags and favourites live in atomic `.discovery.json` sidecars beside the original files. Moving a discovery manually should include its `.viewer.json` and `.discovery.json` companions when present.

Save choices have different meanings:

| Choice | Stored content | Thumbnail |
| --- | --- | --- |
| Preset | Reusable rules, generation recipe, palette and other saved settings | Explicitly labelled generated recipe sample; never an evolved pattern |
| Pattern | Actual completed particle values and rules, rebased to a new initial experiment | Sample of that captured completed state |
| Initial | Original reset baseline | Sample of the original initial positions, even after the live scene evolves |
| Session, CPU action history | Initial state and recorded applied changes | Explicitly labelled **INITIAL** geometry; it does not pretend to show the terminal pattern |
| Captured session, automatic after GPU execution | Canonical actual captures, terminal values, action history and execution/precision metadata | Sample of the actual stored **TERMINAL** capture, labelled with its step and execution precision |

**Save session** automatically chooses the captured-session codec after GPU execution, even if the session has since returned to CPU. The library keeps this kind distinct from an action-only session. For a captured session, **Restore capture** restores stored terminal values, clock and action history exactly on CPU; widened float32 components retain their stored values. Future CPU motion can differ from the recorded trajectory. Choosing GPU continuation is a separate explicit transfer. **Re-simulate CPU** instead starts incremental CPU replay of the recorded actions; it does not restore the terminal pattern and may produce a different trajectory. File parsing/validation stays on the I/O worker, while the execution owner performs only completed-boundary capture/transfer/publication. Replay steps run on the CPU worker, not in a UI-thread replay loop.

Preset and initial saves read immutable settings or the original baseline and do not request current GPU state. Pattern and captured-session saves request the current completed capture explicitly when needed. Selective rule/radius/palette/generation edits use the metadata path without a full state readback. Library thumbnails never request device state while drawing or scanning.

Previews contain at most 256 sampled points. A million-particle preset generates only its bounded preview sample. Refresh scans local metadata/headers on a cancellable background worker, searching all accessible files while retaining only the best 300 matching previews. Folder/share enumeration also stays off the UI thread. A newer search replaces the previous pending request; obsolete results and errors cannot replace the current view. Cancellation takes effect between file reads, so an in-progress operating-system read can finish first. Drawing reads only cached previews. Legacy files remain loadable and show a missing-preview label with an unindexed population, rather than claiming zero particles. If a scientific file changes outside the app, its old thumbnail is hidden; editing its metadata does not make that stale preview current again.

File actions allow one operation at a time. Saves capture completed values on their owner, then immutable prepared data moves to a worker for checkpoint decoding, session validation, JSON serialization, hashing, compression and file writes. Prepared loads pack retained checkpoints and check their storage budget before owner publication. Loads parse and validate on a worker before the owner publishes the prepared state or starts replay. Preparing a new preset population also runs on the worker. Subsequent edits do not change a prepared save. Closing the library cancels its scan but continues an explicit file operation and reports completion without needing to reopen it. Background thumbnail updates retain unrelated focused text drafts. Native shutdown finishes already dispatched artifact writes; a prepared load not yet published is discarded. Failed or unsupported scientific loads retain the active valid experiment. Existing scientific files and viewer companions remain protected against overwrite. If scientific publication succeeds but the optional metadata sidecar cannot be written, the result explicitly reports the saved artifact and a metadata warning; retrying the scientific save under the same name still fails safely because that file now exists.

Select a preset to review its components. **Coefficients**, **Core / cutoff radii**, **Palette only**, and **Future generation** are independent choices. The alignment field lists one source-preset index for each current target species, in order `S0,S1,...`; `-1` explicitly retains that target. A directed pair changes only if both target species are mapped. For example, `1,-1,0` swaps source species 0/1 into target species 2/0 and retains target species 1. Radius imports materialize effective directed tables while retaining unmapped radii and the global parameter values. Palette imports retain camera/effects. Generation imports future recipes/counts and does not create or resample particles. Validation completes before one undoable application; particle identities, motion, clock, execution, playback and unselected components remain.

**Copy current preset** produces strict small preset JSON. **Paste preset for review** validates it and reveals the component/alignment controls without applying it. Clipboard text is limited to 1 Mi characters. Clipboard import accepts presets; large patterns and sessions use files.

**Export .plshare** creates a compressed local artifact. Share that file explicitly; nothing is uploaded or published. **Import share** validates it into a new explicit local filename, then Load / Replay / Preset remains a separate action. The ZIP wrapper has fixed entries `share.json` (wrapper version 1), `document.json`, and an optional `document.json.viewer.json`; it preserves the scientific and viewer-companion UTF-8 bytes exactly. Captured sessions use the canonical captured-session codec inside the share, preserving its captures, action history and provenance. Unknown/duplicate entries, archive-provided extraction paths, unsupported schemas, malformed state, mismatched companion hashes and destination collisions are rejected. Import limits are 256 MiB compressed, 256 MiB per scientific document, 4 MiB per viewer companion and 512 MiB expanded in total. Larger recordings remain explicit uncompressed files; limits never truncate a file while claiming it is complete.

## Consolidated native cases

The [visual checklist](visual-review-checklist.md#observed-progress-and-remaining-coverage) records partial native observations, tested sources and remaining actions. Four CPU save kinds, thumbnails, search beyond 300 items, favourites/rename, selective components, share validation and small GPU capture policy have observed coverage. The detailed cases below retain their full acceptance requirements: large/minimum layouts, query races, focused drafts, worker/shutdown behavior and metadata warnings remain unresolved wherever not explicitly observed. Graphics-free tests do not establish those visual/input results.

| Case | Setup and actions | Expected result |
| --- | --- | --- |
| V18-library | CPU experiment at 500 and 100k; save preset/pattern/initial/session after evolving; inspect thumbnails at normal and minimum window sizes | Four readable kinds; initial/session thumbnails show original geometry, pattern shows captured geometry, preset says generated sample; no draw-time loading stalls |
| V18-find | Add descriptions/tags; favourite, rename display, search by each field; load, reopen and select Recent | Correct filtered cards and recent order; metadata survives reopening; scientific filename and bytes remain unchanged |
| V19-selective | Three target/two source species; map `1,-1,0`; import coefficient, radii, palette and generation separately; undo/redo; try bad index and incompatible periodic radius | Only selected mapped components change, retained entries/particles/clock remain; invalid candidates apply nothing |
| V19-share | Copy/paste a preset, inspect before applying; export/import pattern/session .plshare; try duplicate names and malformed/bound-companion mismatch | Explicit validation and review; imported bytes/values preserved; errors retain active experiment and protected files |
| V18-background | Search a folder with more than 300 items; rapidly change the query/favourite filter and folder while scanning; keep an unrelated text draft focused as a scan completes | UI remains usable; latest request wins; search finds late files; no obsolete error/result or discarded draft; retained cards remain bounded |
| V19-file-worker | Start a large save/import/export and attempt a second file action; keep interacting; simulate a locked metadata sidecar; save then change the live scene before serialization finishes | Only one file operation runs; worker never reads live editor/graphics state; artifact matches its capture boundary; scientific success plus metadata warning is reported accurately |
| V19-close-worker | Close the library during a save and a prepared load, then quit during a dispatched artifact write | File completion is pumped while the modal is closed; pending loads do not wait for reopening; dispatched writes finish at shutdown and queued unapplied loads are discarded |
| V20-capture | Evolve GPU 500/100k scenes, save session, step further, import/export .plshare; restore the saved capture and separately re-simulate CPU; inspect normal/minimum layouts | Captured-session card shows stored TERMINAL geometry; restore returns exact saved clock/values on CPU with continuation notice; re-simulation is distinct and uses CPU worker; settings and bound companion remain valid |
| V20-capture-policy | With GPU state uncaptured after a step, save preset/initial, copy preset and selectively edit components; then save pattern/session and inspect readback counters | Settings/baseline actions cause no full state download; pattern/session request the explicit current capture; normal scanning/drawing causes none |
